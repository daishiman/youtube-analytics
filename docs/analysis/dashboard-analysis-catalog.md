## 1. 取り込むCSVと列

| ファイル | 粒度 | 列（原文） | 保存先テーブル |
|---|---|---|---|
| `表データ.csv` | 動画×期間（先頭行=合計） | コンテンツ, 動画のタイトル, 動画公開時刻, 長さ, エンゲージ ビュー, 平均視聴時間, 平均視聴率 (%), 視聴を継続 (%), ユニーク視聴者数, ユニークリーチ, 視聴回数（共視聴）, 視聴者あたりの平均視聴回数, 新しい視聴者数, リピーター, ライトな視聴者, コアな視聴者, 視聴回数, 総再生時間（単位: 時間）, チャンネル登録者, サムネイルのインプレッション, サムネイルのクリック率 (%) | `video_period_metrics`（期間 from/to 付き） |
| `グラフデータ.csv` | 日×動画 | 日付, コンテンツ, 動画のタイトル, 動画公開時刻, 長さ, エンゲージ ビュー | `video_daily_metrics` |
| `合計.csv` | 日（チャンネル合計） | 日付, エンゲージ ビュー | `channel_daily_metrics` |
| `business-funnel-weekly.csv` | テナント×チャンネル×週 | week_start(JST月曜), channel_id, route_label(省略時LINE), route_visits, inquiries, closed_deals, revenue_jpy | `business_funnel_weekly` |

取込時の判定規則:

- **Shorts 判定**: `視聴を継続 (%)` に値がある、または `長さ` ≤ 180 秒。Shorts は長尺との比較から除外し、別枠で表示する（平均視聴率がループで100%を超えるため。例: 234.85%）。
- **空欄と0の区別**: 空欄は「未提供」（null）、0 は「実測0」。`新しい視聴者数 / リピーター / ライト / コア` が合計行で0・動画行で空欄のときは「このチャンネルでは未提供」と表示し、0として集計しない。
- **集計遅延**: 公開から72時間未満で `ユニーク視聴者数`=0 の動画は「集計中」バッジを付け、比率指標の計算から外す。
- **合計行**: 先頭の `合計` 行はチャンネル合計として別保存し、動画の和とは突合だけ行う（差があっても上書きしない）。
- **週次事業CSV**: MVPは外部providerと自動連携せず、editor以上が手動取込する。`week_start` はJST月曜に正規化し、`tenant_id + channel_id + week_start` で冪等upsertする。空欄はnull、数値の0は実測0として区別する。

## 2. 派生指標（計算式を固定）

| id | 指標 | 式 | 使う枝 |
|---|---|---|---|
| M1 | 加重平均視聴率（長尺） | Σ(総再生時間h×3600) ÷ Σ(エンゲージビュー×長さ) ×100 | 維持 |
| M2 | 推定サムネクリック数 | インプレッション × CTR ÷ 100 | 露出・流入 |
| M3 | サムネ経由比率 | M2 ÷ 視聴回数 | 流入 |
| M4 | ユニーク比 | ユニーク視聴者数 ÷ 視聴回数 | 到達 |
| M5 | エンゲージ比 | エンゲージビュー ÷ 視聴回数 | 維持 |
| M6 | 1日あたりインプレッション | インプレッション ÷ 期間内の公開日数 | 露出 |
| M7 | 登録転換（1,000視聴あたり） | チャンネル登録者 ÷ 視聴回数 ×1000 | 転換 |
| M8 | リーチ→視聴転換 | ユニーク視聴者数 ÷ ユニークリーチ | 露出・到達 |
| M9 | 切り口別インプレッションシェア | 切り口ごとの M6 合計 ÷ 全体 M6 合計 | 露出 |
| M10 | 1本抜き差（leave-one-out） | 1本ずつ除いたときの切り口間の M1 差の最小値 | 維持（頑健性） |

検算: 2026-08-22〜09-19 の長尺8本で M1 = 16.97%（Studio 合計の平均視聴率 16.88% とほぼ一致）。

### 2.1 週次売上ファネル

原因指標は、インプレッション / CTR / 加重平均視聴率M1 / 導線誘導率 / 問い合わせ→成約率の5つ。導線名の既定表示はLINEだが、保存値`route_label`で差し替えられる。結果指標は売上、成約数、登録者数（参考）として原因指標と分ける。週次診断では週境界と出典を揃えるため、YouTube側の原因指標と`views`はStudio CSVだけを使い、API値は詳細画面の公式参考値として混ぜない。

実サンプルのStudio「合計.csv」は2列でインプレッション・CTRを含まないため、現行の取込だけでは5原因指標は揃わない。該当段は入力欠損として判定を保留し、API値や別期間の値から推測して補わない。

- `lead_route_rate = route_visits / views * 100`。`views` は同じJST週のStudio CSV由来値だけを使う。
- `inquiry_close_rate = closed_deals / inquiries * 100`。
- `target_gap = (actual - target) / target`。`target > 0`かつ判定可能で、`target_gap < 0`の原因指標だけを候補にし、その中で最小のものを「最大の改善候補」とする。全指標が0以上なら「全指標目標達成」とし、無理に改善候補を作らない。因果関係や売上への寄与を断定しない。
- `min_sample`と比較する`sample_count`は、インプレッション=インプレッション数、CTR=インプレッション数、M1=エンゲージビュー数、導線誘導率=同週視聴回数、問い合わせ→成約率=問い合わせ数とする。
- 選択週はJST月曜00:00〜翌月曜00:00。翌月曜を迎えていない週、Studio合計CSVの日次7日が欠ける週、M1に使う動画日次の平均視聴率と視聴回数が7日分揃わない週は判定保留とする。Studio合計の日次各行、M1の両入力列に紐づく取込、週次事業CSVのいずれかが週末より前なら鮮度不足とする。過去の確定週に一律TTLは設けない。
- 分母0、入力欠損、`target <= 0`またはtarget未設定、`funnel_targets.min_sample`未達、鮮度不足のいずれかは判定保留とし、0へ丸めない。判定保留理由を画面と分析出力に残す。
- `inquiry_close_rate`は同一週の問い合わせ数と成約数を比べる運用スナップショット（`rate_basis=same_week_snapshot`）であり、問い合わせ発生週に成約を帰属するコホート成約率ではない。画面では「問い合わせ→成約率（同週）」と表示する。
- `funnel_targets` は `metric_id, target_value, min_sample, effective_from` を持ち、対象週に有効な最新設定を使う。

## 3. ダッシュボード（画面 `02-dashboard`）の構成

**表示の2段構え（qa-030 / qa-031、週次売上ファネル追補）**: 週セレクタは上部に固定。最初に見えるのは、次の4ブロックだけ。因果推論ではなく、実績と設定目標の差を示す。

| ブロック | 見せ方 | データ |
|---|---|---|
| ① 結果サマリ | 数値＋前週比。登録者数には「参考」表示 | revenue_jpy・closed_deals・subscribers(参考) |
| ② 5段階の週次ファネル | actual / target / target_gap の横棒。判定不能は理由を表示 | impressions・CTR・M1・lead_route_rate(既定表示LINE誘導率)・inquiry_close_rate |
| ③ 目標未達が最大の改善候補と次のアクション | target_gapが負の判定可能な段のうち最小の1段を強調。全段0以上なら「全指標目標達成」と表示 | funnel_targets / reports / actions |
| ④ 12週推移とデータ品質 | 5原因指標と結果指標の折れ線、取込日時・欠損・min_sample・鮮度バッジ | Studio CSV / business_funnel_weekly / csv_imports |

「詳しく見る」には切り口別比較、視聴者の形、Shorts、個別データ品質を置く。動画別実績はダッシュボードの主領域から外し、動画画面または詳細から見る。図の型は折れ線・横棒・行内横棒・推移線に限る。数字だけのカードや文章だけの区画は作らない。

1. **週セレクタ**: JST月曜始まりの週を選び、前週比と12週推移へ同じ週境界を使う。
2. **結果サマリ**: 売上 / 成約数 / 登録者数(参考)。原因指標と同列の改善候補にしない。
3. **原因ファネル**: impressions / CTR / M1 / lead_route_rate / inquiry_close_rate。
4. **改善候補**: target_gapが負の判定可能な段のうち最小の1段。判定保留時は理由を表示し、全段0以上なら候補を出さず「全指標目標達成」と表示する。
5. **効果比較**: 改善アクションの対象ファネル段の前後値に加え、売上・成約数の下流結果を参考併記する。

## 4. 切り口（コンテンツ分類）

- 既定の分類: **つまずき解決型**（「〜ならない？」「〜わからない？」「なぜ？」のように具体的な困りごとを解く）/ **是非・意見型**（「アリ？」「落ちる？」「炎上覚悟」のように賛否や立場を問う）。
- 分類はAI分析時に提案し、利用者が画面で確定する（`video_angles` テーブル。確定済みは再分析で上書きしない）。
- 新しい型が必要になったら追加できる（例: 体験談型・ハウツー型）。

## 5. 分析解析の内容（AI分析で毎回やること）

### 5.1 問いと読み手（固定の型）

- 問い（既定）: 「今週、売上ファネルで目標未達が最大の原因指標はどれか。次の1手と下流結果は何か」。全指標目標達成時はその事実を結論にし、因果関係は断定しない。
- 読み手: チャンネル運営者。
- 主要指標: impressions / CTR / M1 / lead_route_rate / inquiry_close_rate。売上・成約数・登録者数は結果指標（登録者数は参考）。

### 5.2 定量仮説テンプレート（主張と反対仮説を対で立てる）

| 枝 | 主張テンプレート | 反証条件 | 関数 | 図 |
|---|---|---|---|---|
| 維持 | 切り口Aは切り口Bより M1 が高く、どの1本を除いても向きが変わらない | M10 が0以下 | mannWhitney, describe | hbar |
| 維持（対立） | 差は1本の外れ値による | 1本除くと差が消える | describe | hbar |
| 露出 | 切り口Bは M9 で5割以上を集めるが M1 は全体を下回る | M9 < 0.5 または M1 が全体以上 | describe | stacked |
| 露出（対立） | 露出の偏りは公開の早さによる | 1日あたりに直すとシェア5割未満 | describe | stacked |
| 流入 | サムネ経由 M3 は3割未満で、視聴の大半はYouTubeの表示以外から来ている | M3 ≥ 0.3 | rateCI | hbar |
| 流入（対立） | 視聴の3割以上はサムネ経由 | M3 < 0.3 | rateCI | hbar |
| 到達 | 視聴は少数の繰り返しに集中している（M4 < 0.3） | M4 ≥ 0.3 | rateCI | hbar |
| 到達（対立） | 広い新規到達から来ている（M4 ≥ 0.3） | M4 < 0.3 | rateCI | hbar |
| 転換 | 切り口Aは M7 が高い | 切り口間で M7 の差が信頼区間内 | rateCI | hbar |

各仮説は `採用 / 棄却 / 判定保留（n不足）` で判定し、n と効果量を必ず表示する。前回（2026-09）の判定: 維持=採用（差 3.64pt、最小差 1.59pt）、露出=採用（シェア 0.657）、流入=採用（M3 0.183）、到達=採用（M4 0.214）。

### 5.3 追加データで深める分析（API・ローカル取込）

| 分析 | 入力 | 取得元 |
|---|---|---|
| 離脱場面の特定 | 視聴維持曲線（elapsedVideoTimeRatio × audienceWatchRatio / relativeRetentionPerformance） | YouTube Analytics API |
| 離脱場面の中身 | 文字起こし（タイムスタンプ付き） | SRT/VTT取込（既定）または captions.download（追加同意時） |

### 5.4 心理分析（人が何を考え、何を感じ、どう行動したか）

すべての数字の結果に、次の3段で**推定した心理**を付ける。心理は「推定」と明記し、根拠データと反証条件を必ず添える。

1. **考え（認知）**: 何を期待してクリックし、何を判断して見続け/離脱したか。
2. **感情**: そのとき生まれた感情（好奇心・不安・共感・反発・納得・退屈 など。コメントは Plutchik の8基本感情＋「質問/共感/反論/体験談」の意図で分類）。
3. **行動**: クリック・視聴継続・離脱・再視聴・コメント・登録として表れた行動。

データの形と心理の読み方（既定の解釈表。AIはこれを出発点に、反例があれば修正する）:

| データの形 | 推定する心理 | 確かめる方法 |
|---|---|---|
| インプレッション多・CTR低 | 表示されても「自分の話だ」と感じない（自分ごと化の不足） | タイトルの主語・困りごとの具体性を比較 |
| CTR高・M1低 | サムネ/タイトルで膨らんだ期待と中身のずれ（期待違反） | 冒頭30秒の文字起こしとタイトルの約束を照合 |
| 是非型で露出多・維持低 | 賛否への好奇心で開くが、立場が分かった時点で満足して離れる | 離脱点と「結論提示」の位置を照合 |
| つまずき型で維持高 | 自分の困りごとが解ける見込み（自己効力感）で最後まで見る | 手順説明区間の維持率 |
| M4 ユニーク比が低い | 既存の知り合い・ファンの繰り返し視聴（親しみ・応援） | 視聴者あたり平均視聴回数・コメント主の重複 |
| 特定区間で急落 | 抽象説明・前置き・専門用語で「自分には関係ない/難しい」と感じた | 該当区間の文字起こし・画面 |
| 特定区間で上昇（再視聴） | 手順を確かめたい・見返したい | 該当区間が手順/画面操作か |
| コメントに質問が多い | 分かりかけているが最後の一歩で詰まっている | 質問内容と動画内の説明の有無 |

### 5.5 レポートの構成（毎回同じ順）

1. 問いと結論（1〜3行）
2. 数字の事実（5原因指標のactual/target/target_gap、判定保留理由、結果指標。n・効果量付き）
3. 心理的な読み解き（考え→感情→行動。推定である旨・根拠・確信度）
4. 反対の説明と、それを否定/保留した理由
5. 次の打ち手（対象ファネル段を必須にし、タイトル案・台本・サムネ・導線・問い合わせ対応から1件を選ぶ）
6. 効果測定の予定（対象原因指標の前後値と、売上・成約数の下流結果を比較。因果関係は断定しない）

## 6. AI分析の入出力（Claude Code skill との受け渡し）

- 入力: 期間・動画・派生指標・切り口・週次事業ファネル・目標・（あれば）維持曲線・文字起こし・画像キー・コメント。
- 履歴入力: 同一テナント・同一チャンネルの完了済み分析を新しい順に最大5版。結論・要因・対象ファネル段・改善アクション・baseline/result・下流結果・版番号だけを`analysis_history`として渡し、HTML本体は重複させない。0件は初回分析として正常。
- 出力 JSON: `brief`（問い・仮説）/ `results`（5原因指標、結果指標、target_gap、改善候補・全指標目標達成・判定保留のいずれか）/ `history_review`（参照版、前回仮説の当否、施策効果、前回からの差分）/ `psych_findings`（考え・感情・行動・根拠・確信度）/ `ideas` / `actions`（対象ファネル段付き）/ `report_html`。
- 取込時に JSON を検証し、不正なら取込を拒否して理由を1行で表示する。
