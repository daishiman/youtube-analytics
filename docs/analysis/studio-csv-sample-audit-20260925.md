# Studio CSV 実ファイル監査（2026-09-25）

利用者が指定したレポートフォルダの `analysis.mjs` をたどり、同じエクスポート期間の2組のStudio CSV（計6ファイル）を確認した。チャンネル名・動画タイトル・IDはこの監査記録に転記しない。原本はリポジトリへコピーしていない。

| ファイル | エンゲージ ビュー系列 | 視聴回数系列 | 粒度 |
|---|---:|---:|---|
| 表データ.csv | 10行・21列 | 10行・9列 | 合計1行、動画9行。CSV本文に集計期間なし |
| グラフデータ.csv | 140行・6列 | 140行・6列 | 動画5本×28日。全9本の動画日次ではない |
| 合計.csv | 28行・2列 | 28行・2列 | チャンネル日次 |

2組のフォルダ名は `2026-08-22_2026-09-19` だが、日次CSVの最終行は `2026-09-18`。フォルダの期間を個々のCSVに自動付与しない。表データだけをアップロードした場合、本文からは期間を確定できない。

実CSVでは「長さ」は整数の秒、「平均視聴時間」は `0:01:52` のような時分秒、「サムネイルのクリック率 (%)」は `2.79` のような百分率である。後者は **Studio CSV** の仕様確認であり、Reporting API の `video_thumbnail_impressions_ctr` の数値表現を確定する根拠にはしない。

エンゲージ ビュー系列の表データから、長さ60秒以上の8本について `Σ総再生時間(時間) × 3600 ÷ Σ(エンゲージ ビュー × 長さ(秒)) × 100` を計算すると **16.9721%**。レポート内の17.0%と丸めで一致した。ただし表データの期間がCSV本文にないため、アプリの任意の7日/28日期間KPIへ自動反映する根拠にはならない。

この実ファイル確認に基づき、エンゲージ ビュー/視聴回数の両系列、秒と時分秒の形式、同じ日付の別CSVを取り込む際の値・出典の保持を実装対象とする。欠けた動画・日付を0として補わない。

修正後のパーサーを原本6ファイルへ読み取り専用で実行した結果、**356行すべて受理、未解決0行**。表データのエンゲージ ビュー版は21列中20列、視聴回数版は9列中8列を対応済みと判定した。残る1列は「動画公開時刻」で、原本に保持する。グラフ2ファイルでは各6列中3列を日次数値へ対応させ、タイトル・公開時刻・長さは原本で確認できる。アプリのD1へ実ファイルを取り込む検証は行っていない。
