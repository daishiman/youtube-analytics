【履歴資料】この画像生成プロンプトは初期の週次ファネル案です。現行ダッシュボードの仕様は docs/feat-dashboard-redesign/requirements.md（qa-089〜qa-099）を参照してください。
使用場面: 経営者が毎週、PCまたはタブレットで、売上ファネルのどの段が詰まったかを判断し、次の実験を1件決める。画面はダッシュボード(ナビで選択中)。見出し「ダッシュボード」、問い「今週、売上を止めた段はどこですか？」。期間は今週を既定にして前週へ切り替えられる。
最初に見える情報は、判断順に次の4ブロックだけを置く。視覚的主役はブロック3「今週の改善候補」、主操作は「実験を改善アクションに登録」1つだけにする。
1「今週の結果」: 売上と成約数を正確な大きい数字で表示し、前週差を添える。登録者増は同列のKPIにせず「参考」の小さな補助値にする。週次事業CSVの対象週と最終取込時刻を短い鮮度ラベルで示す。
2「売上につながる5つの原因指標」: インプレッション → CTR → 視聴継続率 → LINE誘導率 → 問い合わせ→成約率（同週）を、左から右へ因果断定ではない診断用ファネルとして接続する。各段に実績(actual)、目標(target)、目標差(target_gap)、前週差、source、freshnessを同じ位置に表示する。インプレッション・CTR・視聴継続率は同一週の「Studio CSV」、LINE誘導率は分子の「週次事業CSV」と分母の「Studio CSV」の2バッジ、問い合わせ→成約率（同週）は「週次事業CSV」バッジにする。「YouTube API」の値をこの5段へ混ぜない。API公式値は詳細画面だけで別表示する。freshnessは最終更新日時か「更新待ち」。分類色を増やさず、主系列はインディゴ、目標線は静かな線、状態は意味色と文字で示す。タブレット以上は横方向、SPは判断順を保った縦方向にする。
3 目標未達が最大の「今週の改善候補」: targetが正で判定可能かつtarget_gapが負の段だけを候補にし、その中で最小の1段を大きく示す。「LINE誘導率が目標を下回っています」のように観測事実として表現し、原因を断定しない。全段が目標以上なら「全指標目標達成」と表示して候補や登録ボタンを出さない。次の実験は1件だけ、仮説・実施内容・来週見る指標を短く並べ、唯一のマゼンタ主ボタン「実験を改善アクションに登録」を置く。
4「12週の推移とデータ品質」: 5指標の12週推移を小さな複数折れ線として同じ尺度規則で比較し、右端に今週を示す。下にデータ品質を1行で置き、欠損、分母0、targetが0以下または未設定、最小サンプル未達、週未確定、週末後の取込なしは0として描かず、該当段へ「判定保留」と不足理由を表示する。
視聴回数・総再生時間・登録者数の大型トップカード、動画別実績表、抽象的なチャンネル評価はこの第一画面に置かず、「YouTube指標の詳細を見る」から動画画面または詳細へ送る。右上の収集状態は「YouTube収集 毎日 3:00」「最終成功」と「週次事業CSV 最終取込」を簡潔に表示する。
