## 1.5 デプロイの方式を理解する（読むだけ。5 分）

### 1.5.1 ダッシュボードの「Create an app」は使わない

Cloudflare のダッシュボードには、**「Workers & Pages」→「Create」→「Import a repository」**（画面名「アプリケーションをセットアップする」／Workers Builds）という、GitHub と直接つなぐ流れがある。**このプロジェクトでは使わない。開いてしまったら「戻る」を押して抜ける。**

使わない理由:

| 画面に出るもの | 実際に起きること |
|---|---|
| 「Wrangler の構成が検出されませんでした。Cloudflare は自動プロジェクト構成を試みます」 | `wrangler.toml` を読めていない状態で、Cloudflare が推測した構成で Worker を作る。D1・R2・Queue・Cron・静的アセットの binding がすべて付かず、起動しても `/api/health` が落ちる |
| 「Git アカウント」「プロジェクト名 youtube-analytics」 | Cloudflare 側が**新しいリポジトリを作る**流れ（「Git リポジトリが作成され、アプリケーションに接続されます」）。既存の `daishiman/youtube-analytics` とは別物になる |
| 「プレビュービルドを有効化」 | PR ごとに preview 環境を作る機能。本構成は production の 1 系統だけと決めている（正本 infrastructure 章 qa-014） |
| 「Your GitHub authorization has expired…」 | Cloudflare の GitHub App の再認可を求めるもの。Git 連携を使わないので、**再インストールも不要** |

このプロジェクトのデプロイは **GitHub Actions が `wrangler deploy` を実行する方式**（`.github/workflows/deploy.yml`）。Cloudflare 側は「API トークンを発行する」以外に、ダッシュボードでの設定は要らない。Worker 本体は初回の deploy 時に自動で作られる。

### 1.5.2 デプロイで何が起きるか

main への push（＝ PR の merge）で `deploy` ワークフローが走り、次の順で実行する。

| # | 実行するもの | 中身 |
|---|---|---|
| 1 | `pnpm install --frozen-lockfile` | `pnpm-lock.yaml` どおりに依存を入れる |
| 2 | 公開準備の検査 | 規約草案、OAuth client ID形式、Cloudflare Secretsのいずれかが未準備なら停止する |
| 3 | `pnpm db:migrate:remote` | `wrangler d1 migrations apply DB --remote`。本番の D1 に未適用のマイグレーションを当てる |
| 4 | `pnpm run deploy` | `vite build`（画面を `dist/web/` へ）→ `wrangler deploy`（Worker と静的アセットを上げる） |

- 認証は環境変数 `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` の 2 つだけ（`wrangler login` は CI では使わない）。
- 同時実行は `concurrency: deploy-production` で 1 本に制限され、前の deploy を打ち切らずに順番待ちする。
- GitHub Environmentは使わず、`pnpm check:release:deploy`を単一の公開前gateにする。このgateはrepository secretsのAPI認証情報を確認した後、`wrangler secret list --format json`でWorker runtime secretの**名前だけ**を検査し、値は取得・表示しない。

### 1.5.3 Cloudflare 側の構成は `wrangler.toml` が正本

ダッシュボードで作った設定ではなく、**リポジトリの `wrangler.toml` が deploy のたびに適用される**。主な中身:

| 設定 | 値 | 意味 |
|---|---|---|
| `name` | `youtube-analytics` | Worker の名前。URL の先頭（`https://youtube-analytics.daishimanju.workers.dev`）になる |
| `main` | `src/index.ts` | 入口。現在は`fetch`（API）だけを持つ |
| `compatibility_date` | `2026-08-22` | 実行環境の版。上げるのは wrangler 更新時だけ |
| `[assets]` | `directory = ./dist/web`、`not_found_handling = single-page-application`、`run_worker_first = ["/api/*"]` | 画面は静的配信。`/api/*` だけ Worker が先に受ける。それ以外の未知パスは `index.html` を返す（React Router のため） |
| `[vars] MAX_TENANTS` | `"75"` | テナント数の上限。非秘密なのでファイルに書く。Queue の無料枠（安全予算8,000操作/日）に収まる数で、上げる前に `tests/platform/queue-budget.test.ts` が通るか確かめる |
| `[vars] GOOGLE_CLIENT_ID` | 6 節で置換する | 非秘密。**シークレットはここに書かない** |
| `[[d1_databases]]` | binding `DB`、`youtube-analytics-db`、`database_id = 91996166-…` | 本番 DB。`migrations_dir = migrations` |
| `[[r2_buckets]]` | binding `MEDIA`、`youtube-analytics-media` | 画像置き場（この feature では宣言だけ） |
| `[[queues.producers]]` | `collect-queue` | producer bindingの予約。consumerは処理と終端失敗契約を実装する次featureで同時に追加 |
| `[triggers] crons` | 未構成 | 空のCronでFree枠を消費しない。UTC 18:00 = JST 3:00 の定期実行は、日次収集の実処理とconsumerが揃う後続featureで追加する |
| `[observability]` | `enabled = true` | ダッシュボードでログとメトリクスを見られるようにする |

**この 3 つは deploy では作られない。別に用意する**:

1. D1・R2・Queue の実体 → すでに作成済み（`scripts/setup-cloudflare.sh`）。
2. Secret（`GOOGLE_CLIENT_SECRET`、`TOKEN_ENC_KEY`）→ 7 節で `wrangler secret put` を使って登録する。`wrangler.toml` には書かない。
3. workers.dev のサブドメイン → 1 節で確認済み。

`wrangler.toml` を変えたいときは、ダッシュボードではなく**ファイルを直して PR を出す**（ダッシュボードで直接いじると、次の deploy で上書きされて元に戻る）。

## 2. Cloudflare API トークンを発行し、GitHub に登録する（10 分）

### 2.1 トークンを発行する

1. https://dash.cloudflare.com/profile/api-tokens を開く（右上の人のアイコン →「My Profile」→ 左の「API Tokens」でも同じ）。
2. **「Create Token」** を押す。
3. テンプレート一覧の **「Edit Cloudflare Workers」** の行の **「Use template」** を押す。
4. 「Token name」を `github-actions-youtube-analytics` に変える（鉛筆アイコンで編集）。
5. **「Permissions」** 欄: テンプレートの行（Workers Scripts: Edit など）はそのまま残す。**「+ Add more」** を押して、次の 2 行を追加する。

   | 左（種類） | 中（対象） | 右（権限） |
   |---|---|---|
   | Account | D1 | Edit |
   | Account | Queues | Edit |

   - テンプレートに最初から入っている権限（Cloudflare 公式の一覧で確認済み）: Account の Workers Scripts、Workers KV Storage、Workers R2 Storage（いずれも Edit）、Account Settings、User Details、Memberships（いずれも Read）、Zone の Workers Routes（Edit）。R2 は含まれているので追加不要。
   - 追加した結果、Permissions 欄に `D1` と `Queues` の行があることを確認する。D1 がないと main の deploy の `db:migrate:remote` が、Queues がないと `deploy` が権限エラーで止まる。
6. **「Account Resources」** 欄: `Include` / `Daishimanju@gmail.com's Account` を選ぶ（「All accounts」にしない）。
7. **「Zone Resources」** 欄: `Include` / `All zones from an account` / `Daishimanju@gmail.com's Account` を選ぶ（独自ドメインは使わないが、テンプレートがこの欄を求めるため）。
8. 「Client IP Address Filtering」は空のまま（GitHub Actions の IP は固定されないため）。
9. 「TTL」は空のまま（期限なし）。期限を付ける場合は、期限が来る前に 2.2 をやり直す必要がある。
10. **「Continue to summary」** を押す。内容を確認して **「Create Token」** を押す。
11. 表示されたトークン（長い英数字）を **「Copy」** でコピーする。**この画面を閉じると二度と表示されない。** メモ帳などには保存せず、そのまま 2.2 に進む。

## 4. OAuth 同意画面を設定する（15 分）

3. ロゴは空のままにする（ロゴを入れると Google の審査が必要になる）。
4. 一番下の **「保存」** を押す。

**承認済みドメインの欄には、ドメイン名だけを入れる。** URL ではない。

| 入れるもの | 例 | 可否 |
|---|---|---|
| ドメイン名だけ | `daishimanju.workers.dev` | ○ |
| `https://` 付き | `https://daishimanju.workers.dev` | × 「無効なドメイン: スキームを指定することはできません」 |
| パス付き（リダイレクト URI） | `https://youtube-analytics.daishimanju.workers.dev/api/auth/callback` | × 同上。これは 5 節のクライアント画面で登録するもの |
| localhost | `http://localhost:8791/...` | × 登録不要。Google は localhost をリダイレクト URI としてだけ特別に受け付ける |
| 親ドメイン | `workers.dev` | × 他人のサブドメインまで名乗れてしまうため拒否される |

登録する承認済みドメインは **`daishimanju.workers.dev` の 1 つだけ**。欄が 2 つ以上あるときは、余った欄を消してから保存する。

| Google で「エラー 400: redirect_uri_mismatch」 | 5 のリダイレクト URI と実際の URL が 1 文字違う | エラー画面の「詳細」に出る URI を、そのまま 5 に追加する |
| Google で「アクセスをブロック: このアプリは…テスト中」 | 4.4 が「テスト中」のまま | 「アプリを公開」するか、テストユーザーに追加する |
| ログイン後に `/login?error=OAUTH_FAILED` | クライアント ID かシークレットの誤り | 6 の値と 7 の Secret を見直す（`pnpm wrangler secret put GOOGLE_CLIENT_SECRET` で上書きできる） |
| ログイン後に `/login?error=OAUTH_STATE_MISMATCH` | ログイン画面を 10 分以上放置した | もう一度ログインする |
| 「現在新規の受付を停止しています」 | テナント数が `MAX_TENANTS`（75）に達した | `runbook.md` の 6.1 |
| Cloudflare の画面で「Wrangler の構成が検出されませんでした」 | Git 連携（Create an app）の画面を開いている | 「戻る」で抜ける。この方式は使わない（1.5.1） |
| Cloudflare の画面で「Your GitHub authorization has expired」 | 同上 | 再認可も GitHub App の再インストールも不要。画面を閉じる |
| `youtube-analytics` が Workers & Pages に見当たらない | まだ一度も deploy していない | 11 の deploy が緑になると現れる。急ぐなら手元で `pnpm run deploy` |
| 本番の `/api/health` が `"db": false` | D1 の binding か `database_id` の不一致 | `wrangler.toml` の `database_id` と `pnpm wrangler d1 list` の値を照合する |
| 本番で画面が真っ白、`/login` が 404 | `dist/web` が入っていない | `pnpm run deploy` は `vite build` を含む。Actions のログで `vite build` の成功を確認する |
| 詳しい運用 | — | `docs/feat-platform-tenant-auth/runbook.md` |
